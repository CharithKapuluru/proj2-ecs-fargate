STEP 1: VERIFY AWS IDENTITY
================================================================================

Command:
  aws sts get-caller-identity

Output:
  {
    "UserId": "AIDAXJWZ62WC3IC6Z27KW",
    "Account": "501894534533",
    "Arn": "arn:aws:iam::501894534533:user/test_user"
  }

What this tells us:
- UserId: Unique identifier for your IAM user
- Account: Your 12-digit AWS account number
- Arn: Full "address" for your IAM user

ARN format breakdown:
  arn:aws:iam::501894534533:user/test_user
  │   │   │   │             │    │
  │   │   │   │             │    └── Resource name
  │   │   │   │             └─────── Resource type
  │   │   │   └───────────────────── Account number
  │   │   └───────────────────────── Service (iam)
  │   └───────────────────────────── Partition (aws)
  └───────────────────────────────── Always "arn"

If this works: ✓ AWS CLI is configured correctly

================================================================================
STEP 2: VERIFY AWS REGION
================================================================================

Command:
  aws configure get region

Output:
  us-east-1

Why us-east-1?
- Cheapest pricing
- Most AWS services available
- Most mature and stable region
- New features launch here first

Configuration files:
  ~/.aws/config       # Region, output format
  ~/.aws/credentials  # Access keys (sensitive)

Important: Keep all resources in the same region!

================================================================================
STEP 3: CREATE BUDGET ALERT
================================================================================

Command:
  aws budgets create-budget \
    --account-id 501894534533 \
    --budget '{
      "BudgetName": "proj2-cost-guardrail",
      "BudgetLimit": {"Amount": "10", "Unit": "USD"},
      "TimeUnit": "MONTHLY",
      "BudgetType": "COST",
      "CostTypes": {
        "IncludeTax": true,
        "IncludeSubscription": true,
        "UseBlended": false
      }
    }' \
    --notifications-with-subscribers '[
      {
        "Notification": {
          "NotificationType": "ACTUAL",
          "ComparisonOperator": "GREATER_THAN",
          "Threshold": 80,
          "ThresholdType": "PERCENTAGE",
          "NotificationState": "ALARM"
        },
        "Subscribers": [
          {"SubscriptionType": "EMAIL", "Address": "your-email@example.com"}
        ]
      }
    ]'

Key parameters:
- BudgetLimit: $10/month
- Threshold: 80% ($8) - get alerted before hitting limit
- NotificationType: ACTUAL (vs FORECASTED)
- Email: Confirm subscription when you receive the email!

Verify budget exists:
  aws budgets describe-budgets --account-id 501894534533

Verify notifications:
  aws budgets describe-notifications-for-budget \
    --account-id 501894534533 \
    --budget-name proj2-cost-guardrail

================================================================================
KEY SERVICES OVERVIEW
================================================================================

ECR (Elastic Container Registry)
--------------------------------
- Store Docker images in AWS
- Private registry for your account
- ECS pulls images from here
- Registry URL: <account-id>.dkr.ecr.<region>.amazonaws.com

ECS (Elastic Container Service)
-------------------------------
- Run Docker containers on AWS
- Fargate: Serverless (no EC2 management)
- Components: Cluster → Service → Task → Container

VPC (Virtual Private Cloud)
---------------------------
- Your private network in AWS
- Contains subnets (public/private)
- Security groups control traffic
- We'll create a custom VPC (not use default)

IAM BASICS
================================================================================

Your setup:
  AWS Account: 501894534533
  └── IAM User: test_user
      ├── Access Key: AKIAXJWZ62WCSNDTHYVE
      ├── Secret Key: <stored in ~/.aws/credentials>
      └── Policy: AdministratorAccess (allows everything)

AdministratorAccess policy:
  {
    "Effect": "Allow",
    "Action": "*",
    "Resource": "*"
  }

This is fine for learning. In production, use least-privilege policies.

How authentication works:
1. AWS CLI reads credentials from ~/.aws/credentials
2. Creates cryptographic signature using secret key
3. Sends signature (NOT the secret key) to AWS
4. AWS verifies signature
5. Checks IAM permissions
6. Executes request if allowed

Security: Your secret key never leaves your machine!
